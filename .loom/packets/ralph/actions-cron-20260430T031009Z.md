# Task For This Iteration

Build, in one bounded slice:

1. **`scripts/apply_views.py`** — idempotent view-apply runner:
   - `load_dotenv()`.
   - Read `motherduck/views.sql`, replace literal `${R2_BUCKET}`
     with `os.environ["R2_BUCKET"]`.
   - `duckdb.connect(f"md:?motherduck_token={os.environ['MOTHERDUCK_TOKEN']}")`.
   - `con.execute(sql)`.
   - Print `view materialized` on success.
   - Top-level `if __name__ == "__main__": main()`.
   - On any exception, raise (non-zero exit).
   - Must not require additional dependencies beyond what
     `pyproject.toml` already declares.

2. **`scripts/health_check.py`** — per-slug N→0 detector:
   - `load_dotenv()`.
   - Connect to MotherDuck (same shape as `apply_views.py`).
   - Run a single SQL statement that:
     - Reads R2 raw zone with the standard glob and guards:
       ```sql
       FROM read_parquet('r2://${R2_BUCKET}/raw/*/*/*.parquet',
                         filename = true,
                         union_by_name = true)
       WHERE filename NOT LIKE '%/_dlt_%'
         AND source_kind IS NOT NULL
         AND ats_slug IS NOT NULL
         AND role_id IS NOT NULL
       ```
     - Groups by `source_kind, ats_slug, fetched_at` to compute
       per-fetch role counts.
     - Uses `qualify ROW_NUMBER() OVER (PARTITION BY source_kind,
       ats_slug ORDER BY fetched_at DESC) <= 2` to keep the latest
       two fetches per slug.
     - Pivots / self-joins so each
       `(source_kind, ats_slug)` row exposes both `latest_count`
       and `prior_count`.
   - For each row:
     - if `prior_count IS NULL`: print
       `[health] new slug seen: source_kind=... ats_slug=...
        latest_count=...` (informational, do not fail).
     - if `prior_count > 0` and `latest_count == 0`: print
       `[health] REGRESSION: source_kind=... ats_slug=...
        prior=N latest=0`. Mark a regression flag.
     - else: print `[health] ok: source_kind=... ats_slug=...
        latest=N prior=M`.
   - At the end: if any regression flagged, exit 1; else exit 0.
   - The 0-match-is-honest case (sitemap/gohunt always at 0,
     page/regrid always at 0) must NOT trigger a regression —
     prior_count must have been positive at some point for it to
     count.

3. **`.github/workflows/refresh.yml`** — daily cron + per-source
   isolation + view-apply + health-check:
   - `name: Refresh radar pipeline`
   - `on:` triggers:
     - `schedule:` `cron: "0 12 * * *"` (daily at 12:00 UTC)
     - `workflow_dispatch: {}` for manual runs
   - `concurrency: { group: refresh, cancel-in-progress: false }`.
   - `permissions: { contents: read }`.
   - One job `refresh` on `ubuntu-latest`. Steps:
     1. `actions/checkout@v4`
     2. `astral-sh/setup-uv@v3` (or current major) with
        `enable-cache: true`
     3. `uv sync` (hatchling builds the project as a wheel)
     4. **Per-source steps**, each with `continue-on-error: true`:
        - `python -m dream_job_radar.pipelines.greenhouse`
        - `python -m dream_job_radar.pipelines.ashby`
        - `python -m dream_job_radar.pipelines.sitemap`
        - `python -m dream_job_radar.pipelines.page`
        Each step has its own `id:` for downstream
        `if: always()` checks.
     5. `python scripts/apply_views.py` — `if: always()` so the
        view DDL is reapplied even if a source step failed.
     6. `python scripts/health_check.py` — REQUIRED (no
        `continue-on-error`). Failure here fails the job and
        triggers GitHub's email-on-failure for the repo owner.
   - All steps inherit env from a job-level `env:` block that maps
     all five secrets:
     ```yaml
     env:
       R2_ACCESS_KEY_ID: ${{ secrets.R2_ACCESS_KEY_ID }}
       R2_SECRET_ACCESS_KEY: ${{ secrets.R2_SECRET_ACCESS_KEY }}
       R2_ACCOUNT_ID: ${{ secrets.R2_ACCOUNT_ID }}
       R2_BUCKET: ${{ secrets.R2_BUCKET }}
       MOTHERDUCK_TOKEN: ${{ secrets.MOTHERDUCK_TOKEN }}
     ```
   - Do NOT pin to dated action versions; use major
     (`@v4`, `@v3`).

4. **`README.md`** updates:
